# Баг-репорты: QA Mentor (Telegram-бот)

## BUG-001: В режиме «Postman-тесты» бот нумерует строки кода, скрипт не выполняется в Postman

* Связанные тесты: режим 4, POST /posts (см. `postman/api-tests.md`)
* Шаги воспроизведения:

  1. Открыть меню, нажать «🔌 Postman-тесты».
  2. Отправить описание запроса POST /posts с телом JSON `{"title": "test", "body": "hello", "userId": 1}`.
  3. Вставить скрипт от бота в Postman: Scripts → After response.
  4. Нажать Send.
* Ожидаемый результат: скрипт выполняется, тесты запускаются.
* Фактический результат: Postman выдаёт «Couldn't evaluate the test script: SyntaxError: Unexpected identifier 'pm'». Строки скрипта начинаются с «1.», «2.», «3.», «4.».
* Воспроизводимость: наблюдался в запросе POST /posts. В запросах GET /users/1 и GET /users/9999 скрипты приходили без нумерации, поведение нестабильно.
* Гипотеза причины: в промпте есть правило «нумерованные списки», и модель применила его к коду.
* Окружение: n8n Cloud, Telegram, Gemini `models/gemini-3.1-flash-lite`, Postman, 19 октября 2026.
* Severity: Major. Основная функция режима выдаёт неработающий код, но проблема обходится ручным удалением номеров.
* Priority: Medium.
* Доказательство: `docs/05-bug-mode4-syntax-error.png`.
* Исправление: в блок режима 4 системного промпта добавлено правило «Код выдавай чистым JavaScript, без нумерации и без номеров перед pm.test. Комментарии начинай с //».
* Повторная проверка после исправления: \[Повторная проверка не проводилась: в N из 3 запросов нумерация не появилась].
* Статус: Fix applied.

## BUG-002: Режим 2 добавляет в баг-репорт детали, которых пользователь не указывал

* Связанный тест: M2-04
* Шаги воспроизведения:

  1. Меню → «🐞 Ревью баг-репорта».
  2. Отправить: «Шаги: 1. Открыть каталог. 2. Нажать «В корзину» у любого товара. 3. Открыть корзину. Ожидаемый результат: товар в корзине. Фактический результат: корзина пустая. Окружение: Chrome 130, Windows 11.»
* Ожидаемый результат: бот структурирует отчёт только по указанным данным, недостающее помечает как неизвестное; Severity и Priority с обоснованием.
* Фактический результат: в Actual Result добавлено «счётчик товаров отображает «0»», в Environment «Chrome 130.0.6723.70»; Priority: High без обоснования.
* Воспроизводимость: наблюдался в 1 запуске, повторные запуски не проводились.
* Окружение: n8n Cloud, Telegram, Gemini `models/gemini-3.1-flash-lite`, 19 октября 2026.
* Severity: Major. Бот вносит в документ для разработчика непроверенные факты; проблема обходится ручной проверкой.
* Priority: Medium.
* Доказательство: `docs/m2-04-fabricated-details.png`.
* Статус: New.
